# Дополнительное сравнение GPT-6.1 Terra — Phase 20

По указанию автора от 3 ноября 2026 года к ранее ограниченному CodeAgent
исследованию добавляется конкретная модель GPT-6.1 Terra. Предыдущие данные,
рукопись и выводы сохраняются. Новый результат не объявляется улучшением до
завершения и проверки опыта. Автор: Россинский Андрей Евгеньевич.

## Условия до основного прогона

- Модель `gpt-6.1-terra`, установленный Codex CLI 0.164.0, сохранённая
  ChatGPT-авторизация. Используется квота этой учётной записи. API-ключи
  не запрашиваются и не передаются. Штатная проверка туннеля сохранена.
- Точные данные Phase 18: по 192 случая в with-rules / without-rules,
  12 инструментов, шесть областей. Все контракты, исходные вызовы и эталоны
  совпадают с прежним опытом. Модель получает только recovery_input.
- Для исполнения используется замороженное ядро `fda30006`, source digest
  `ccd2591e512801b45a81d0a1c426c802a5b380ec680ae03c13c2fd31efd24397`.
  Новый CLI-транспорт находится в examples, его хеш входит в model_versions.
  Исходный код ядра не меняется для дополнительной модели.
- Методы B3, D0, D1, B2, M1; три повтора, два условия, всего 5760 решений.
  Четыре workers, пауза одна секунда после решения, сначала with-rules.
- Mapping-2.0, обычная генерация JSON без принудительного output-schema:
  схема передаётся в исходном тексте так же, как в опыте CodeAgent.
  До двух попыток в общем бюджете 120 секунд.
- Reasoning effort явно low, service tier default. Температура и предел
  выходных токенов не управляются этим CLI; manifest отмечает provider_default.
  Поле max_tokens=2048 исходного LLMRequest здесь лишь неподдерживаемая
  подсказка интерфейса. Локальные пределы ответа/операций остаются прежними.
  Поэтому равенство токенного бюджета или настроек генерации не заявляется.
- Одноразовая сессия, пустой временный каталог, игнорирование пользовательского
  config, отключённые инструменты/подагенты/плагины/память/поиск, нулевой лимит
  AGENTS.md. Системный текст заменён исходными инструкциями mapping-2.0.
  Ошибки и непредусмотренные события не принимаются как корректный ответ.
- Нейтральные пробы подключения и pilot из восьми вариантов documents_words,
  профиль 0, по пяти методам в двух условиях (80 решений) исключены из основных
  показателей. Выбор задан до ответов; гиперпараметры по качеству не подбираются.
  После исправления только протокола пилота основной объём не зависит от его
  благоприятности. Неудачные пробы сохраняются отдельно.

## Анализ и ограничения

Основные сравнения — CRR и UHR M1 и B2 с историческим CodeAgent на тех же
случаях и повторах. Исходные знаменатели, ошибки провайдера и ложные отказы
сохраняются. Парный bootstrap пересэмплирует 12 целых инструментов, 2000 выборок,
seed 42; чувствительность — шесть областей. Повторы не являются независимыми
инструментами. P-значения описательные, без поправки на множественные сравнения.

Дополнительно B2V проверяет уже сохранённые кандидаты обоих генераторов без
новой генерации и полной политики риска M1. Его время — сумма сохранённых
компонентов, а не живой сквозной замер. Повторяемость и попытки анализируются
существующими проверенными функциями.

Сравнение с историческим CodeAgent включает различия клиента, настроек и
сетевых условий: в прежнем опыте было прерывание сети. Оно не устанавливает
чистое причинное превосходство модели. Сервисные ревизии неизвестны. Два
сервиса на авторских локальных API не заменяют внешней репликации и сами
по себе не подтверждают исходную H3 о переносимости на разные семейства.

Первая нейтральная проба отклонена: Codex отправил стартовое предупреждение
об experimental-флаге отключения поиска локальных skills как item типа error.
Диагностика показала ответ `{"ok":true}`, но транспорт его не принял. Перед
основным опытом выключен только вывод этого известного предупреждения;
остальные error/tool события по-прежнему приводят к отказу. Исходные FAIL
и диагностический поток сохранены в preflight. Это не результат бенчмарка.

## Изменение по прямому указанию автора: перезапись провайдерных отказов

После обнаружения сбоев автор потребовал повторно обратиться к модели и
перезаписать неудачные записи в основной матрице. До этого изменения
подготавливается проверенная копия исходных metadata и заменяемых записей
в before-provider-retry; исходные полные результаты фиксируются в Git.

Выбор задаётся до дополнительного прохода: только ABSTAIN без разобранного
предложения, у которого последняя ошибка попытки — ProviderError. Успешный
ответ после внутреннего retry, содержательный отказ модели, ошибка JSON
или некорректный адаптер не выбираются. В завершённом with-rules таких
провайдерных отказов 476; without-rules ещё выполняется.

Для каждого выбранного наблюдения разрешён один дополнительный проход с
прежними двумя попытками/120 секундами. Фактический новый исход заменяет старый
даже при ухудшении оценки. Модель не получает метки или эталон. Перезапись
атомарна, возобновление не повторяет уже полученный ответ. Затем заново
вычисляются сводки, хеши и fingerprint с явной provider_retry_policy.

В итоговых records сохраняются исходные попытки/ошибки и новые трассы.
CLI calls складываются; неизвестное полное использование остаётся null.
Задержка заменённых записей — сумма компонентов, не новое сквозное время.
Отчёт покажет исходную и пересчитанную оценки. Это дополнительная политика
восстановления после сбоя, а не исходный опыт с одинаковым бюджетом попыток.
У исторического CodeAgent такого дополнительного прохода нет; чистое
превосходство модели по исправленной матрице не устанавливается.

```sh
PYTHONPATH=/path/to/experimental-source/phase18-fda30006/src .venv/bin/python examples/terra_provider_retry.py --executable /Users/dennrbone/bin/codex
```
