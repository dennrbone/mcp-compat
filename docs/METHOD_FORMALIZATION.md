# Проверка восстановленного вызова

Вызов состоит из имени инструмента и аргументов. Его контракт задаёт схему
аргументов и может задавать схему ответа. Кандидат — вызов, подготовленный для
новой версии инструмента.

## Предварительная проверка

`EvidenceVerifier.verify` проверяет, что обработчики привязаны к нужным
контрактам, и сверяет оба вызова со схемами. Оператор задаёт профиль наблюдений.
Профиль перечисляет части состояния и подтверждает полноту наблюдения,
замкнутость среды, детерминированность и однозначный выбор версий.

Каждую версию запускают дважды. Каждый запуск получает отдельную копию
одного начального снимка. Сравнивается пара из ответа и конечного состояния.
Перед сравнением данные приводятся к единому представлению. Например, числа
`1` и `1.0` считаются равными. Если выходная схема объявлена, ответ также
проверяется по ней.

Успех сохраняется в свидетельстве формата `admission-evidence-3`. В нём
закреплены контракты, вызовы, снимок, профиль, обработчики и результат проверок.

## Финальное решение

`admit` сверяет актуальный снимок со снимком в свидетельстве, повторяет
сравнение и проверяет совпадение полученной записи с предварительной.
При расхождении возвращается `ABSTAIN`. При успешных проверках возвращается
`EXECUTE` с адаптированным вызовом.

Результат связан с проверенными вызовами и состоянием. При операциях с побочными
эффектами приложение связывает допуск с исполнением через транзакцию или
атомарную проверку версии состояния.
