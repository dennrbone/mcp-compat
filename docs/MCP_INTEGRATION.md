# Интеграция с MCP SDK 1

Основное окружение использует официальный Python SDK `mcp==1.30.0`.
`make_server(contract, implementation, state)` публикует инструмент и его
контракт. Сервер проверяет имя и аргументы вызова. Структурированный ответ
в этом интерфейсе представляет собой объект JSON. При наличии выходной
схемы сервер проверяет возвращённый обработчиком словарь по ней. Готовый
`CallToolResult` передаётся клиенту как есть. Валидатор обрабатывает ссылки
на схемы локально.

`make_proxy(old, new, upstream, strategy, context=..., timeout=...)`
публикует прежний контракт. Прокси получает решение стратегии, проверяет
адаптированный вызов и передаёт его связанному серверу. Структурированный
ответ должен соответствовать прежней выходной схеме. При отказе,
превышении времени ожидания или ошибке связанного сервера клиент
получает результат MCP с `isError` и решением `ABSTAIN`.

`serve_stdio(server)` обслуживает MCP через стандартный ввод и вывод.
Пример `examples/mcp_server.py` публикует инструмент `check_migration`
с тестовым реестром. Он возвращает решение о переносе вызова.
Подключение прикладного клиента описано в [инструкции](CLIENT_INTEGRATION.md).

## Проверки

```sh
.venv/bin/python -m pytest -q tests/test_mcp.py
```

Тесты проверяют открытие сессии, `ping`, каталог инструментов, вызовы,
валидацию входа и результата, отказ, тайм-аут и разрыв соединения.
Отдельная проверка запускает сервер в дочернем процессе и обращается
к нему через стандартный ввод и вывод. В экспериментах из статьи
Hybrid вызывается из Python, а доверенные версии инструментов
запускаются изолированно через MCP. [Воспроизведение](REPRODUCIBILITY.md).
