## Проблема

Структурно допустимое преобразование ранее корректного вызова может менять
результат или побочный эффект. Нужно решить задачу **допуска конкретного
кандидата** при заданных версиях, состоянии и наблюдении, отделив её от поиска
кандидата и от последующей оценки по закрытому эталону. Автоматическое
восстановление из одной схемы в общем случае невозможно: одинаковые схемы
допускают разные реализации. Два таких мира дают алгоритму одинаковый вход,
но требуют разных решений. Без дополнительных свидетельств необходим отказ.

## Предшествующая математическая основа

Сопоставление полей — schema matching, а не новая операция: Rahm, Bernstein,
2001, *A survey of approaches to automatic schema matching*, DOI
[10.1007/s007780100057](https://link.springer.com/article/10.1007/s007780100057).
Изменение API и миграция по рефакторингам: Dig, Johnson, 2006,
[авторский текст](https://dig.cs.illinois.edu/papers/JSME_API_Evolution.pdf),
DOI 10.1002/smr.328. Сравнение исходов — differential testing: McKeeman,
1998, [первичный текст](https://www.cs.tufts.edu/comp/150FP/archive/bill-mckeeman/DifferentailTesting.pdf).
Равенство ошибочных реализаций не устанавливает правильность по спецификации.

Regression verification рассматривает доказательство эквивалентности близких
программ, а не только один наблюдавшийся прогон: Godlin, Strichman,
*Regression verification*, DAC 2009, DOI 10.1145/1629911.1630034.
Издатель ACM в этой сессии вернул 403; описание ограничено доступной авторской
[первичной работой о подходе](https://citeseerx.ist.psu.edu/document?doi=c0107f9683b7cbbdde7643fb391387d7e39e7622&repid=rep1&type=pdf).
Наш свидетель — запись конечной проверки, не доказательство эквивалентности
программ и не замена SMT/индуктивных инвариантов.

Машинно проверяемые свидетельства исполнения не новый общий принцип.
Proof-carrying code использует формальное доказательство политики, тогда как
наш replay повторяет доверенные вычисления для одного входа. Сопоставление:
[Necula, Schneck, ISSS 2002, авторский текст и Coq](https://people.eecs.berkeley.edu/~necula/ISSS02/).
Термин «сертификат» здесь не означает PCC, цифровую подпись или аппаратную
аттестацию. Сам JSON с хешами не разрешает исполнение.

Проверялись запросы API migration / contract evolution / schema matching /
regression verification, а также русские эквиваленты. Использованы arXiv,
IEEE, ACM, Springer, веб-индексация Scholar/Semantic Scholar и российские
источники. Найденные коммерческие описания и нерелевантные тексты не включены
в доказательство новизны. Доступ к каждому каталогу не гарантирован;
поиск не заявляется исчерпывающим систематическим обзором.

Новая близкая работа: Li R., Wang H., Zhang Y., Zhang W.,
[Correspondences as Decisions: JevNexus for Decision-Centric Schema Matching](https://arxiv.org/abs/2610.09487),
2026. По первичной аннотации она разделяет парные решения и refinement по
свидетельствам. Поэтому разделение генерации и проверки и экономия вызовов
сами по себе также не объявляются нашим исключительным вкладом. Прямое
экспериментальное сравнение с JevNexus не выполнено; задачи и метрики различаются.

## Содержательный вклад, подлежащий проверке новым опытом

1. Формальный критерий допуска **экземпляра миграции** с явными предпосылками
   полноты наблюдений, доверия и воспроизводимости состояния.
2. Расширение существующего evidence до версии, связывающей обе схемы, вызовы,
   реализации, профиль, начальное состояние, результаты структурной проверки
   и сравнение **результата вместе с состоянием**. Повторная проверка не читает
   эталон бенчмарка и не доверяет записанному `passed`.
3. Парное экспериментальное разделение структурного допуска, старой проверки,
   строгой проверки и контроля полноты на одинаковых внешних кандидатах.

Это уточнение и проверяемая специализация известных механизмов для эволюции
MCP. Приоритет нового общего алгоритма не установлен. Эффект расширения пока
не приписывается старым 432/432; его требуется измерить в новом наборе.

## Необоснованные утверждения

Нельзя утверждать: первое восстановление MCP/API; новый принцип witness;
полную эквивалентность программ; защиту от неизвестного внешнего эффекта;
production-безопасность; необходимость LLM при точных правилах; превосходство
над всеми системами миграции; статистическое преимущество над статьями с иными
задачами/датасетами. Декларация полноты оператора — предпосылка, не результат
автоматического обнаружения всех скрытых зависимостей.
