## Назначение

Проверить вклад источника правил и независимой верификации в восстановление
входных вызовов MCP. Выбор журнала в эту работу не входит. Научная новизна
подлежит сопоставлению с предшествующими работами; приоритет не предполагается.

Исходный полный прогон Phase 16 сохраняется как наблюдавшийся ранее результат.
Его данные, оценки и неудачные ответы не заменяются после доработок. Новый
эксперимент не переименовывает этот набор в независимую контрольную выборку.

## Phase 17: дополнительные детерминированные контроли

- D0 исполняет явно заданные `context.rules` и проверяет новую схему.
- D1 использует ту же проверку операций, адаптер, независимые реализации и
  ограничения M1, но получает операции непосредственно из правил без LLM.
- Ни один контроль не генерирует фиктивный модельный ответ и не считает
  детерминированные вычисления обращением к модели.
- Оба метода выполняются на всех 2160 замороженных сценариях evobench-1.2.
- Контроль добавлен после просмотра Phase 16; это дополнительный анализ,
  а не заранее зарегистрированный исходный baseline.
- При сравнении разных запусков сохраняются оба manifest, source fingerprint
  и сведения об условиях. Основные доли сравнимы на одинаковых сценариях;
  скорость последовательного контроля и нагруженного CLI не приравнивается.

## Phase 18: независимая прикладная проверка

До запросов CodeAgent фиксируются следующие условия:

- 12 новых прикладных инструментов в шести предметных областях: документы,
  календарь, склад, сообщения, аналитика, бронирование. Эти реализации не
  используют функции генератора старых 48 инструментов.
- Два разных входных примера на инструмент, восемь вариантов эволюции:
  добавление optional-параметра, переименование инструмента, переименование
  параметра, вложенная структура, кодирование числа строкой или массивом,
  переименование enum, удаление существенного параметра, изменение результата
  или побочного эффекта. Итого 192 сценария, 12 кластеров инструментов.
- Первые шесть вариантов допускают восстановление, последние два требуют
  отказа. Метки и эталонные результаты проверяются до ответов модели.
- Два условия доступности информации: явно переданные операции миграции и
  отсутствие готовых операций. Контракты, старый вызов, реализации и эталонные
  исходы внутри пары одинаковы. Условие входит в отдельный digest данных.
- Восстановимые варианты не требуют угадывания отсутствующих констант или
  неизвестных коэффициентов. Типовые преобразования имеют единственную
  зарегистрированную реализацию в своей прикладной среде: неоднозначные
  контракты исходного набора 1.2 задним числом не исправляются.
- Методы: B3, D0, D1, B2, M1. Три полных повтора в каждом условии:
  192 × 5 × 3 × 2 = 5760 решений. Число запросов к модели меньше числа решений.
- Четыре параллельных workers; пауза одна секунда после решения. Условия
  запускаются последовательно: сначала с готовыми правилами, затем без них.
- Только установленный GigaCode CodeAgent, текущий идентификатор модели и
  версия CLI, mapping-2.0, temperature=0, max_tokens=2048, до двух попыток
  в общем бюджете 120 секунд. Неизвестная ревизия сервера указывается явно.
- После заморозки кода и данных настройки не подбираются по ответам. Любая
  необходимая правка создаёт новую версию запуска с сохранением предыдущей.

## Независимость проверки

Прикладные обработчики старого и нового API определяются отдельно от таблицы
эталонных исходов. Верификатор получает доверенные обработчики и копии состояния,
но не метки, идентификаторы сценариев или эталонный адаптер. Оценка после решения
сравнивает фактическое поведение с отдельно заданным эталоном.

Официальный MCP SDK используется для проверки реального протокольного обмена
между версиями и proxy. Массовая оценка качества отображений и протокольные
интеграционные проверки описываются отдельно. Никаких реальных платежей или
пользовательских данных. Верификатор не является изоляцией произвольного Python.

## Статистика и критерии отчёта

Основные показатели CRR/UHR/FBR сохраняют исходные знаменатели. Неудачные запросы
и неподдерживаемые случаи включаются в основные показатели, неизвестные значения
стоимости/токенов остаются null. Дополнительное поддерживаемое подмножество
публикуется только вместе с общей оценкой.

Для разности CRR используются парные bootstrap-интервалы с пересэмплированием
целых инструментов (2000 выборок, seed 42). Проверка устойчивости группирует
инструменты по предметной области. Перестановочный тест меняет знак целого
кластерного контраста; его допущение — обменность методов внутри кластера при
нулевой гипотезе. До 16 ненулевых кластеров применяется полный перебор, иначе
9999 перестановок с поправкой +1. Это не устраняет все зависимости общих шаблонов.

Повторы одного инструмента остаются в том же кластере. Отдельно показываются
результаты каждого повтора, стабильность решений и разброс; повторные наблюдения
не объявляются новыми независимыми инструментами. Один CodeAgent не проверяет H3.
Нулевой наблюдаемый UHR не является доказанным верхним пределом риска в production.

Дополнительно на одинаковых кандидатах B2 оценивается эффект независимой
верификации без повторного запроса к модели. Такой replay-контроль обозначается
отдельно, с источником каждого кандидата и раздельным учётом исходных модельных
затрат и добавочной проверки. Он не подменяет полный M1 с его политикой значений.


## Зафиксированное прерывание, без изменения кода и параметров

После начала опыта доступ через текущий сетевой proxy стал возвращать HTTP 503,
а модельные попытки — повторяющиеся ProviderError. Новые запросы остановлены
после 1118 сохранённых решений. Полный набор из 5760 не считается полученным.
Все записанные решения, включая ошибки, сохранены; их хеши записаны отдельно.
При восстановлении связи продолжение использует тот же fingerprint и не
перезаписывает завершённые ответы. Использование незаписанных запросов,
которые находились в работе при остановке (не более четырёх одновременно),
остаётся неизвестным; итоговое число физических запросов не будет выдаваться
за точный полный учёт. Событие: `case-study/network-interruption.json`.

Соединение восстановлено пользователем. GitHub HTTP 200 и отдельная проба
CodeAgent PASS подтверждены до продолжения; прежние 1118 хешей совпали.
Продолжение не заменяет ошибочные ответы; событие `network-resume.json`.
