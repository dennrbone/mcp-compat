Дата 04.11.2026. Основной дополнительный опыт V2:
`experiments/external-admission-2026-11-04-v2/`; код до опыта —
`1dcaffe3adfc09bc64052cfa4e22e825fb05b361`. Анализ и исходные таблицы:
`experiments/external-analysis-2026-11-04-v2/analysis.json`, `metrics.csv`,

## Единицы и сравнения

Три внешних репозитория, две линии происхождения, четыре инструмента,
63 уникальных случая: 8 исторических переименований, 4 исторических benign-
контроля Calculator, 51 авторское вмешательство (17 одинаковых типов × 3).
Повторы наблюдений не являются новыми случаями. 441 решение — это 63 × 7
методов. Выполнены 1453 попытки business tool-вызова, ошибок источников 0;
initialize/list и вспомогательные протокольные сообщения в это число не входят.
Новых модельных запросов — 0. Исторические CodeAgent/Terra не перезапускались.

A–E получают **один и тот же заранее заданный кандидат**, пустой context правил
и одинаковые public inputs. A — прежний SandboxVerifier (результат для
Filesystem/Calculator, состояние для SQLite). B — EvidenceVerifier плюс final
admit/replay и фактически заданные декларации профиля. C — только input schema.
D — тот же механизм B, но принудительно считает полноту, замкнутость,
детерминизм и однозначность подтверждёнными; current-state gate сохраняется.
E — complete=False даже для положительных случаев. M1_old/M1_new — полный
Hybrid **без mapper**, с прежним/новым verifier; M1_new вызывает admit. Hybrid
может предложить identity и отказаться из-за opaque, поэтому он оценивается
отдельно от фиксированного кандидата A–E. Проверка результата и состояния не
равна поиску миграции или оценке возможностей модели.

Gold открыт после всех решений. Он явно подготовлен по исходникам и fixture,
не вычислен EvidenceVerifier. Второго независимого разметчика не было. Полнота
профиля предоставлена исследователем, а не выведена автоматически; в отрицательных
контролях это информативный вход, а не заслуга детектора скрытого состояния.
Способность автоматически получать такой профиль не измерялась.

## Статистика и чувствительность

Использован существующий bootstrap по целым base_tool (2000 выборок, seed=42),
парность по одному случаю, точная перестановка меток методов целыми кластерами.
Единицы — три репозитория; чувствительность — две lineage-группы, где FS/SQLite
объединены, и исключение каждого источника. Обменность меток и независимость
кластеров не установлены дизайном случайной выборки; p и интервалы являются
условным разведочным анализом, без подтверждающего семейства гипотез.

| Сравнение | Δ CRR | Δ UHR | 95% cluster bootstrap для Δ UHR | p, 3 источника | p, 2 lineage |
|---|---:|---:|---|---:|---:|
| B − A | 0 | −0,4375 | [−0,55; −0,3571] | 0,25 | 0,5 |
| B − C | 0 | −0,55 | [−0,55; −0,55] | 0,25 | 0,5 |
| B − D | 0 | −0,25 | [−0,25; −0,25] | 0,25 | 0,5 |
| M1_new − M1_old | 0 | −0,5172 | Не определён: 75/2000 выборок без EXECUTE | 0,5 | 0,5 |

У последней пары lineage-интервал [−0,5882; −0,4167]. При исключении FS,
SQLite, Calculator точечная Δ UHR B−A составляет соответственно −0,4706,
−0,3571, −0,4706; B−D всегда −0,25. Для полного M1 исключение Calculator/
SQLite оставляет соответственно 464/504 неопределённых bootstrap-выборок;
они не удаляются ради удобного интервала. Полные значения находятся в JSON.
FBR B−A: +0,0333, интервал [0; 0,1], p=1; B−C: +0,1, вырожденный интервал,
p=0,25. Δ CRR всех пар 0, p=1. **Статистически значимое преимущество не
установлено**. Вырожденный bootstrap при повторении одинаковых шаблонов в
трёх источниках не означает отсутствия неопределённости; p и интервалы могут
не согласовываться как взаимно обратные тесты из-за разных процедур/малого n.

Ноль ошибок не означает нулевой риск. Для события «хотя бы один unsafe в
исполняющем источнике» условная односторонняя 95%-я граница Clopper–Pearson
при iid источниках и k=0 равна 1−0,05^(1/n): **0,6316 для B (n=3)**,
**0,7764 для M1_new (n=2)**. Это граница для события уровня источника,
**не доверительная граница UHR отдельного вызова**. При lineage n=2 для B
аналогичная граница 0,7764. При данной целевой выборке iid не обоснована;
без модели популяции нет нетривиальной гарантии, верхняя граница UHR остаётся
1. Для E без исполнений оценка ошибки не определена. Интервал [0;0] обычного
bootstrap UHR B не используется в качестве доказательства безопасности.
